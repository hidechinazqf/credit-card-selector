# 信用卡选卡助手（纯静态 · 开源）

一个**零依赖、零后端**的信用卡对比 / 筛选 / 推荐工具。用户既可以按条件自己筛，也可以做一份问卷让系统帮 TA 推荐合适的卡。

> 定位：**纯信息分享**，不代办、不跳转申卡、不收费、不导流。适合个人技术分享、博客配套、或作为"如何做选卡工具"的开源模板。

---

## ✨ 功能

- 🔎 **多条件筛选**：银行、档位、年费承受、卡组织、关键词、仅看学生可办、仅看在售
- 🏷️ **按权益筛选**：贵宾厅 / 接送机 / 酒店会籍 / 健康医疗等 10 类，支持「满足其一 / 满足全部」两种匹配；卡片正面权益标签可直接点击联动筛选
- 🧭 **问卷推荐**：5 个问题，按身份 / 年费 / 用途 / 看重 / 出行频率打分推荐 Top 3
- ⚖️ **卡片对比**：勾选最多 3 张并排对比差异
- 📄 **卡片详情**：年费、实际成本、核心权益、办卡门槛、核验状态
- 🗂️ **四档全覆盖**：学生低门槛 → 免年费 → 积分抵年费 → 刚性年费高端
- 📱 **移动端适配**：纯前端响应式，手机也能用

技术栈：原生 HTML + CSS + JavaScript，没有任何框架和构建步骤。

## 🚀 本地运行

因为浏览器禁止用 `file://` 直接读取本地 JSON，请用一个本地静态服务器打开：

```bash
cd credit-card-selector
python3 -m http.server 8000
# 然后浏览器打开 http://localhost:8000
```

或者直接用 VS Code 的 "Live Server" 插件、或任意静态服务器（如 `npx serve`）。

> 部署到 GitHub Pages / Cloudflare Pages / 任意静态托管后，直接访问域名即可，无需本地服务器。

## 🔧 换成你自己的卡

所有卡片数据都在 `data/cards.json`，一份数组，每张卡一个对象：

```json
{
  "bank": "招商银行",
  "cardName": "运通百夫长白金",
  "cardOrg": "运通",
  "tier": 4,
  "annualFee": "3600",
  "realCost": "3600",
  "benefits": "PP卡、万豪/希尔顿会籍、洗牙、高尔夫、88元健身",
  "eligibility": "大众可申(主动申请)",
  "verifyStatus": "✅在售",
  "verifyDate": "2026-08-15",
  "note": "替代已停发经典白",
  "perks": [
    {"cat": "贵宾厅", "text": "PP卡（Priority Pass）主卡不限次全球机场贵宾厅"},
    {"cat": "酒店会籍", "text": "自动匹配万豪金卡、希尔顿金卡会籍"},
    {"cat": "健康医疗", "text": "每年1次免费口腔护理（洗牙）"},
    {"cat": "运动健身", "text": "高尔夫练习场免费12次/年；88元/月星级酒店健身"},
    {"cat": "其他", "text": "年费3600元/年，刚性不可减免"}
  ]
}
```

字段说明：

| 字段 | 含义 |
|---|---|
| `bank` | 发卡行 |
| `cardName` | 卡名 |
| `cardOrg` | 卡组织（银联 / Visa / 万事达 / 运通 / 套卡 …） |
| `tier` | 档位：`1` 低门槛/学生，`2` 免年费，`3` 积分抵年费，`4` 刚性年费高端 |
| `annualFee` | 年费规则描述 |
| `realCost` | 实际年成本（数字，用于"年费承受"筛选与问卷；非数字可用"极高"等） |
| `benefits` | 核心权益关键词（列表卡片展示、筛选关键词、问卷匹配都靠它） |
| `perks` | 完整权益清单（数组，每项 `{cat, text}`）。`cat` 从固定分类取：贵宾厅 / 接送机 / 酒店会籍 / 健康医疗 / 运动健身 / 返现 / 里程积分 / 出行保障 / 生活礼遇 / 其他。详情弹窗按类分组展示，搜索也会覆盖这些明细 |
| `eligibility` | 办卡门槛 / 准入条件 |
| `verifyStatus` | 核验状态：`✅在售` / `⚠️需更新` / 其他 |
| `verifyDate` | 核验日期 |
| `note` | 备注（停发替代、缩水提示等） |

改完保存刷新页面即可，无需重新构建。

## 📌 数据来源与核验（重要）

本仓库的卡片数据是**社区维护的快照**，不是银行官方接口，也不是"保证准确"的权威来源。请务必理解它的边界：

- **初始数据如何产生**：26 张卡由 4 个联网调研 agent 于 **2026-08-15** 分档核对（在售 / 停发 / 权益缩水），落盘时每张带 `verifyStatus`（✅在售 / ⚠️需更新）和 `verifyDate`（核验日期）。部分权益次数 / 年费若当时无法 100% 确认，会在文本里标「(待核实)」——这是诚实标注，不是疏漏。
- **为什么不能保证永远对**：信用卡年费、权益缩水极快（2026 年多家银行已调价），任何静态快照都会过时。所以数据里专门保留 `verifyStatus` / `verifyDate`，让**新鲜度可追踪**。
- **你看到的是谁的版本**：本仓库主页会显示「N 在售 / M 待复核」与核验日期；每张卡详情也展示核验状态与日期。**别人 Fork 出去改发布的版本，内容质量由他们自己负责**，与本仓库无关。
- **发现错了怎么办**：提 Issue 或 PR 修正即可，记得把 `verifyDate` 更新为当天、状态有疑问就标 `⚠️需更新`（见贡献指南）。

> 再次强调：本工具仅做信息整理与对比，**不代办、不跳转申卡、不收费、不导流**。一切以银行官方为准。

## 🤝 贡献指南

欢迎提 Issue / PR：补充新卡、修正权益、优化推荐算法、增加新维度（如返现比例、积分价值）等。**信用卡权益变动很快，数据时效性比代码更重要。**

### 提交一张新卡

1. Fork 本仓库，新建分支（如 `add-cmb-card`）
2. 编辑 `data/cards.json`，在数组里追加一个对象（字段见上方表格）：

```json
{
  "bank": "XX银行",
  "cardName": "卡名",
  "cardOrg": "银联 / Visa / 万事达 / 运通 / 套卡",
  "tier": 1,
  "annualFee": "免年费",
  "realCost": "0",
  "benefits": "一句话核心权益，用于列表与关键词搜索",
  "eligibility": "办卡门槛 / 准入条件",
  "verifyStatus": "✅在售",
  "verifyDate": "2026-08-15",
  "note": "可选：停发替代、缩水提示等",
  "perks": [
    {"cat": "贵宾厅", "text": "具体权益描述（含次数 / 门槛）"}
  ]
}
```

3. **字段约定（请务必遵守，否则筛选 / 展示会出错）**
   - `tier` 只能取 `1` / `2` / `3` / `4`，含义见字段表
   - `realCost` 用于年费筛选与问卷打分，请填**数字**（如 `0`、`3600`）；非数字请填 `极高` / `高`
   - `perks[].cat` 只能从固定分类取，不要自造新类目：
     `贵宾厅` / `接送机` / `酒店会籍` / `健康医疗` / `运动健身` / `返现` / `里程积分` / `出行保障` / `生活礼遇` / `其他`
   - `verifyStatus` 用 `✅在售` 或 `⚠️需更新`；`verifyDate` 填你核对的当天日期
4. 本地用 `python3 -m http.server 8000` 打开，确认新卡能正常筛选 / 详情 / 对比
5. 提交 PR，并在说明里写清**信息来源**（官网页面 / App 截图 / 客服确认等），方便他人复核

### 修正已有卡

直接改对应对象即可，记得把 `verifyDate` 更新为当天，状态有疑问就改成 `⚠️需更新`。

### 代码改动

逻辑全在 `assets/js/app.js`，无构建步骤、无依赖。改完刷新页面即可验证，无需重新打包。

### 别忘了溯源

每次新增 / 修正卡片，请：① 更新对应卡的 `verifyDate`；② 在 [`CHANGELOG.md`](CHANGELOG.md) 追加一条带日期的条目（含信息来源）。这样无论谁 Fork、改到哪一版，都能追溯"这张卡的数据是哪天、凭什么核的"。
